The initial Rust research solver is implemented and locally verified. The repository is
`sandsowkd/vgc-solver`; the project, package and binary are NashDex. Work lives in this
`nashdex` clone, separate from the enclosing Pokémon LLM repository. No intermediate commits
were made. Implementation, experiments and documentation were completed before final delivery.

## Measured findings

Apple M5, 10 logical CPUs, 32 GiB, macOS arm64, optimized Rust build; illustrative authored fixtures.

- Full 60×96 root, 32 samples/cell = 184,320 full-game rollouts: **3.62–3.70 seconds** across
  seeds 11/29/47, matrix gap below 0.001. Mixtures still varied markedly; statistical bounds remain wide.
- Principal random baseline: about **36,949 complete battles/s**, 154,835 turns/s on one thread.
  These are short no-reserve games, not standard four-mon VGC throughput.
- Fixed four-sample root matrix: sampling 1,140 ms at one thread vs 467 ms at ten (~2.44×).
- 100 ms failed full pair coverage and returned no strategy. 500 ms–10 s sweeps completed coverage,
  with reported uncertainty; a small empirical gap did not certify the true root payoff matrix.
- 3,600 side-swapped evaluation games in total: 2,400 baseline games, 900 solver endgame games,
  300 reduced 2v2 solver games. No draws/truncations. Greedy beats random in the authored doubles
  positions; tactical adds no demonstrated strength. Solver-versus-greedy intervals overlap 50%
  widely. No advantage over greedy or tournament strength is established.
- Separate peak-memory measurement is recorded in `benchmarks/memory.json`.

See `docs/benchmarks.md` and structured JSON records for exact configurations, timings, confidence
intervals, seeds and matchup-selection limitations. Hosted CI status is available in GitHub Actions;
its local formatting/lint/test and reference equivalents passed before delivery.

## Remaining limits / blockers

No environment blocker remains: Rust was installed and the pinned reference built successfully.
The limits are research/correctness scope rather than missing infrastructure:

- This solves an estimated **root matrix under fixed continuation policies**, not the extensive-form
  battle game. Strong continuation bias and Monte Carlo uncertainty can dominate solver convergence.
- Only pinned Reg M-C is validated. No reserves, voluntary switching, hidden information, learned
  values, selective-depth search or frontend. No PokePaste URL or human Showdown-text importer.
- Protect/redirection/survival/setup/Mega-form policy reasoning needs substantial improvement.
  The small authored evaluation corpus contains trivial/overwhelming positions and is not metagame evidence.
- Complex Transform/Illusion/revival/residual histories need more differential coverage. Advanced
  projection import is not universal lossless checkpoint restore; exact replay is preferred.
- Direct one-mon doubles initialization crashes the pinned Showdown oracle (`forceSwitchFlag` on null).
  Differential games start 2v2; direct 1v1 is locally tested in Ninjask. No dependency patch was hidden.
- Exact chance enumeration is experimental and branch-limited. Soft time budgets may overshoot a
  started rollout or solver check block. Incomplete/censored matrices deliberately yield no point strategy.
- The owner has not chosen a blanket license for original NashDex code. Dependency/data MIT notices
  and implications are documented; no third-party player team corpus was redistributed.

## Highest-value next task

Build a larger frozen held-out corpus emphasizing nontrivial defensive/mixed decisions, then add
variance reduction/confidence-guided root sampling with initial coverage of every legal pair.
Evaluate stability, calibration and per-turn playing strength against multiple continuation policies.
Use that evidence to guide stronger continuation policies; do not optimize merely for a small sampled
matrix Nash gap. See ROADMAP.md for prioritized follow-on work.
